Multi-Seller Marketplace Channel

A second channel inside an existing marketplace app: independent sellers open shops in the same app, cart and checkout. I designed it end to end and wrote most of its core services.

01 —

Four hard rules

Each problem, side by side with how it was solved.

1
ProblemTwo channels, one cart and checkout
+ detailTwo channels had to share one cart and one checkout, while stock, payment and order flows stayed separate per seller.
SolutionA cart extended with a channel flag so both channels coexist in one basket; one checkout session groups child orders, one per seller, under one payment.
2
ProblemThe last unit, without idle locks
+ detailStock is limited per variant. Two buyers must never both get the last unit, but idle carts should not lock stock either.
SolutionStock is held when the buyer opens the checkout summary, not when they add to cart, and released when they leave or the hold expires.
3
ProblemConfirmations: late, twice, or never
+ detailPayment confirmation is asynchronous. It can arrive late (after the buyer cancelled), twice, or not at all.
SolutionCancel, payment confirmation and a background payment check all go through the same locked path, so the order ends in one consistent state whichever arrives first.
4
ProblemSeveral sellers in one checkout
+ detailOne checkout can include orders from several sellers, and each can be cancelled or refunded on its own.
SolutionA per-seller order lifecycle with cancellation, return and refund cases, and seller income credited only after a buffer period.

01

Stock correctness under concurrency

Row locks on the variant before checking availability.

+

Row locks on the variant before checking availability; a separate held counter, so on-hand stock only changes when an order is really paid or returned; a fixed lock order (variant, then hold) everywhere.

02

Late and duplicate payment events

A late confirmation revives a cancelled checkout; a duplicate does nothing.

+

Cancel asks the payment provider first and does not cancel if the provider is unreachable; a late confirmation revives a cancelled checkout instead of losing a paid order; a duplicate confirmation does nothing; a background check recovers payments whose confirmation never arrived.

03

Idempotent refunds

Every refund and restore step checks whether it already ran.

+

Every refund and restore step checks whether it already ran, so retries and double clicks are safe. A shared payment is marked partially refunded while other orders in the same checkout are still paid.

04

Explicit state machines

Shops, holds, orders, refunds and return cases.

+

Explicit state machines for shops, holds, orders, refunds and return cases, with a status history per order.

05

Scheduled jobs that cannot overlap

Seller income credited once, with a timestamp guard.

+

Scheduled jobs that cannot overlap, and seller income credited once with a timestamp guard.
